## 1. Integrated Test Case Description & Overview

### 1.1 Purpose & Scope
This document outlines the complete **System Integration Testing (SIT)** scenarios for the **Feedback Analysis System**. Integration testing verifies that individual software components, background microservices, external cloud APIs, and persistence layers interact correctly according to system specifications.

The test scope spans across all multi-tier component boundaries:
1. **Client Frontend (SPA):** React 19, Vite, TanStack Query v5, Tailwind CSS, Recharts, Lucide Icons, Sonner Toaster.
2. **Application Server (REST API):** Node.js, Express 5, Drizzle ORM, JWT Authentication, Multer file streaming.
3. **AI Worker Microservice:** Python 3.10, PyABSA, FastText, PyTorch, Uvicorn/FastAPI, S3/R2 streaming client.
4. **Relational Database:** PostgreSQL (Neon Serverless) with relational cascades and transactions.
5. **Object Storage Service:** Cloudflare R2 / AWS S3 API for secure CSV review dataset storage.
6. **Payment & Billing Gateway:** Stripe API (Subscriptions, Invoices, Webhook verification, Hosted Invoices).
7. **Email Notification Service:** Nodemailer SMTP (Account recovery, suspension alerts, feedback responses).

---

### 1.2 System Architecture & Integration Points

The integration scenarios validate data flow across the following primary architectural pipelines:

```
[Retailer / Admin Browser]
       │
       ▼  (HTTPS / REST / JWT)
[Express Application Server] 
  ├── Authentication & RBAC Middleware
  ├── Storage Quota Middleware
  └── Stripe Webhook Controller
       │
       ├──► [PostgreSQL Database (Neon)] (State, Subscriptions, Datasets, Reviews)
       ├──► [Cloudflare R2 Object Storage] (Raw CSV Uploads & Retention)
       ├──► [Stripe Gateway] (Subscriptions, Incomplete Checkouts, Paid Invoices)
       ├──► [Nodemailer SMTP] (Verification OTPs, System Alerts, Ticket Replies)
       │
       ▼  (HTTP / Polling / Health Watchdog)
[Python ABSA Worker Service] (Aspect Extraction, Sentiment Polarity, Triplet Persistence)
```

### 1.5 Evaluation Criteria & Result Nomenclature

Each test scenario is evaluated against multi-tier assertion criteria:
- **UI State Assertion:** Visual components, forms, spinners, modals, and Sonner toast notifications.
- **HTTP / API Contract Assertion:** Accurate HTTP status codes (`200`, `201`, `400`, `401`, `403`, `404`) and JSON payloads.
- **Persistence Assertion:** Database row inserts, updates, and relational cascade deletes in PostgreSQL.
- **External Side Effect Assertion:** Stripe subscription state, Cloudflare R2 file existence, SMTP email delivery.

**Result Statuses:**
- **Pass:** All steps completed as expected across UI, API, DB, and external microservices.
- **Fail:** Any discrepancy between Expected and Actual behavior.
- **Blocked:** Precondition failure preventing scenario execution.
